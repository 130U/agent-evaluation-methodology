# 当前研究可以怎样答辩

2026-09-17。最新证据包括G3真实未采用候选、G4共享反馈对照的停止记录，以及C1完整12卡合成准入校准。以下区分已有发现、具体改良与尚未得到的效果证据。

## 一句话解释研究问题

评测能够告诉我们一次任务是否完成，但这个结果不自动说明 Agent 错在哪里，更不能自动决定下一版策略应该怎样改。本研究检查既有诊断是否有足够依据进入优化，并检验这一步是否值得其成本。

## 目前已经有证据的部分

| 结论 | 实际证据 | 解释限制 |
|---|---|---|
| 完整性是解释评分的前提 | 固定真实上游评价类，40 题×14 类受控输出，以及 74 个无断言控制；有效结果保留，指定不完整结果归为 unknown | 故障由实验注入，不是自然错误频率 |
| 任务低分不自动给出责任归属 | 订阅 G1 开发任务 59 未取消、未改址，官方零分合理；“较早订单”在可见返回中缺少明确绑定，澄清后用户结束 | 单例不能证明任务设计错误，也不能证明 Agent 无任何可改进之处 |
| 有些失败可以由可见证据明确定位 | 开发任务 76 已用工具算出历史消费总额，却只写入内部转接摘要，没有向用户回答 | 沟通遗漏可修改，不等于修正后整题必然成功 |

| 准入组件能区分指定正负对照 | 一条未确认地址变更诊断获接纳；已明确确认的对照中，同类“不曾确认”诊断被拒收 | 两条合成情境的真实模型审查，不能估准确率或自然收益 |
| 优化器可在真实环境执行其合法终点 | G2两臂各完成2个episode，训练满分，官方GEPA均跳过反思；S0未变 | 0反思、0候选，不称已实证完整策略生成循环；接口测试预设分数也不是研究效果 |
| 真实训练改善不足以采用候选 | G3 B1训练从1/2变为2/2；官方验证持平2/2，但候选新增缺乏政策依据的退款时限承诺，合格数降至1/2 | 用户披露也发生变化，训练变化不能唯一归因于策略；GEPA已因验证持平保留S0，不把此功劳单独归给共同验收 |

| 可见的 assistant 行为未必受待优化策略控制 | N1 唯一被接受的诊断批评框架固定开场；源码和真实调用确认第一次模型回复已请求认证；E4 的 36 次不同策略初始化保留相同开场 | 揭盲后发现，原标签未改；并非 18 条框架消息都被误诊 |
| 严格归责可能排除可执行的改进建议 | N1 的查单建议在前缀中可实施，但“Agent 必须先查单”的义务未确立；相关整条诊断被拒收或弃权 | 可执行不保证有效；本轮没有下游损益估计 |
| 来源资格检查可以补充语义审查 | C1固定12卡：5充分建议获准、3错误拒收；不足层语义收2条，来源核对额外拦截其中1条框架开场 | 仍有1条证据不足建议获准；仅合成准入资格，没有送入实际优化，不估自然准确率 |

## 创新在哪里

原生 τ2 reviewer 已经做 Agent/用户归责并给出修正建议；GEPA 已经反思与验收候选；CAST 等已有行动时前缀 critique。不能把这些原则改名后作为创新。

本项目拟检验的增量是：**在不更换 reviewer、优化器或任务评分的条件下，选择性接纳现成诊断，是否降低错误建议的影响，同时保留足够有效反馈？** 当前实现不为 B2 添加解释性证据卡，而只选择原诊断。因此 B1/B2 的直接差异是诊断选择；若再要归因于语义选择而非减少文本量，还须补同数量/近似长度的随机选择对照。

目前已经有证据支撑的增量更具体：**发现并复核一个语义准入仍不能排除的框架来源误归责，把反馈对象与本次策略干预范围显式绑定。** 这应表述为可复现案例及机制改良。AgentGrad 等已有通过干预进行提示归责的研究，因此不能宣称首次提出“改正确的组件”；相关工作核验见 [补充说明](../../supporting-evidence/tau-feedback-evidence/research/ACTION_ORIGIN_RELATED_WORK.md)。

若被追问“是否保证能提升”，回答：不保证。E4 确认了修改 system prompt 无法改写预置开场，来源检查能排除这种无效目标；但拒收其他诊断也可能损失局部有用建议。研究已经得到可验证的机制结论，任务收益需要单独检验。

若被追问“到底有没有跑出新策略”，回答：有。G2先观察到满分跳过的合法终点；随后另行登记G3，在两臂统一关闭满分跳过，各自真实生成并重新执行一个候选。B2未超过父代训练表现，B1虽改善训练分数，验证未形成可采用更新，最终都保留初始策略。没有改写G2，也没有补跑追求正结果。

若被追问“没有提升，项目价值在哪里”，回答：我们把优化中的三种错误拆开并留下了可复核证据：评分记录不完整、把框架行为归给策略、把官方满分误当作所有客户承诺都有依据。具体改良是将原生诊断与执行来源及可修改范围绑定，再独立检查候选。现有结果支持这些检查的必要场景，但没有证明它们一定带来净性能收益。

若被追问“为什么不直接多跑几次直到提升”，回答：G3每臂一次候选，达不到采用条件就保留旧策略；G4预先给了四批共享反馈对照，但在父代阶段触发用户有效性STOP。我们保留两版终点，没有通过改题、重试或同题新版本追求正结果。先前研究局限可以推动新设计，但不能把新设计写成旧实验已成功。

若被追问“实现是否全在实验前冻结”，回答：主要运行代码、输入、上游版本和协议已固定，但原选择封存器在GEPA保留S0且存在候选验证行时发生身份绑定冲突。我们保留原源，另外发布v2和修正说明，核验后才封存策略并测试。报告及公开导出工具也在登记后编写，不追记为预先冻结。

若被追问“最终测试是不是完整跑完”，回答：没有。原计划36次，第一轮18次完整，第二轮首个单元因网络流错误触发严格STOP，留下1次中断和17次未运行。我们保留固定分母，不补跑、不将缺失改成失败。三组策略相同，pass²及完整回归率不能估计；报告的价值在真实反例、归责改良和可核查的采用边界，不能说已证明性能提升。

若被追问“C1是否说明你的审查器已经可靠”，回答：没有。它保留了5条充分支持建议、拒收了3条明确错误建议；但语义层仍接纳了2条证据不足建议，来源检查只额外拦住其中1条。这个结果支持把来源检查独立出来，同时也暴露语义审查的过度确信。5/5是固定合成卡的计数，不能当自然场景召回率。

若被追问“G4是不是证明了方向错误”，回答：没有走到比较阶段，不能证实或否定性能假设。4个环境完成，116个优化episode未运行，8个提案未开始；测试策略尚未选出，因此最终至多36条只是设计上限。停止原因得到独立复核支持，说明本轮证据不足以继续做有效的优化比较。方法的净收益仍是开放问题。

若被追问“工程成熟度体现在哪里”，回答：固定版本与源文件、行动时信息隔离、逐调用及输出绑定、预算和STOP、未知值保留、独立标签封存与同一公式重放均有实现和检查；本机最终562项测试通过。完整G4选择器用120条虚构工件检查原协议契约，未冒充真实成功运行。这些是研究工程证据，没有做生产负载、安全或跨环境部署认证。

## 哪些结果会推翻预期

- 自然 reviewer 几乎不产生无依据诊断，筛选空间很小。
- GEPA 的反思或共同验证已经足以消除坏反馈影响，额外准入只增加成本。
- 准入过于保守，拒收了“应该先询问”这类有效建议。
- 诊断层更准确，却没有策略收益；覆盖损失或其他瓶颈抵消收益。
- 当前开发配置失败覆盖不足，原定自然收益比较不能启动。

这些结果都应进入报告。研究方向合理，是指问题可证伪、实验能够区分解释；不是指正向结果已经确定。

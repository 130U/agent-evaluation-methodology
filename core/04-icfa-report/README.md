# Agent Evaluation Methodology

## 基于 τ-bench 的 Agent 评测有效性与反馈优化研究

**2026.05 — 2026.09**

本项目于 2026 年 5 月启动，2026 年 9 月完成。

### ICFA（Intervention-Constrained Feedback Admission）：干预约束反馈准入

[GitHub 项目](https://github.com/130U/agent-evaluation-methodology) · [项目概览](../../projects/tau-bench/README.md)

## 摘要

能够对话、调用工具并执行任务的人工智能系统，通常被称为智能体（Agent）。让智能体根据失败经验修改行为，是提高其可靠性的一条重要路径。然而，任务失败、错误责任与修改方案之间并不存在自动成立的对应关系：一条反馈即使指出了真实问题，也未必适合用来修改当前允许调整的系统组件。

本研究以 τ2-bench 的文本零售任务为实验环境，结合 GEPA 反思式提示优化，研究反馈进入策略更新前应满足的证据条件，并将所实现的方法概括为**干预约束反馈准入（ICFA）**。该方法联合检查评价完整性、行动时信息和行为来源，将反馈的使用资格与本轮允许修改的系统部分绑定，再通过回归验收判断是否采用策略修改。

研究的核心贡献，是把反馈质量研究落实到三个可分别检验的问题：**诊断是否成立、修改对象是否匹配、修改结果是否有效。** 源码审计、受控实验与真实交互案例，为这一分层提供了可复核的证据。

## 研究启发

| 研究来源 | 对本项目的启发 |
|---|---|
| [ALE · Agents’ Last Exam](https://arxiv.org/abs/2606.05405v2) | 将评测放回真实工作流与可验证结果中，促使本项目关注“一个分数究竟证明了什么”，把评测有效性作为研究起点。 |
| [τ2-bench](https://arxiv.org/abs/2506.07982) | 通过交互环境与细粒度分析区分错误来源，为本项目提供文本零售任务、业务政策和可追踪的执行过程。 |
| [GEPA](https://arxiv.org/abs/2507.19457) | 从执行轨迹中反思并生成提示词修改，启发本项目进一步研究“哪些反馈有资格进入优化”，并沿用其候选生成与测试机制。 |

三条研究思路汇合于本项目的核心问题：**让评测结果有证据，让优化反馈有归属，让策略更新有验收。**

## 一、研究背景：为什么反馈也需要被评价

智能体的表现取决于模型、提示词、工具、运行框架及用户交互。一次失败可能来自模型判断，也可能来自工具能力、用户信息或框架行为。最终得分能够描述任务结果，却不足以单独确定责任，更不能直接给出有效的修改方向。

本研究使用两个已有研究基础。τ2-bench 提供任务、业务政策、模拟用户和工具环境；项目选取其中的文本零售任务，例如查询、取消和退换订单。GEPA 则通过阅读执行轨迹、反思问题、生成并测试提示词修改来优化系统。这里的“策略修改”主要指系统提示词更新，不涉及模型权重训练。[τ2-bench 论文](https://arxiv.org/abs/2506.07982)、[固定版任务环境与实现](../03-tau-feedback-evidence/RESEARCH_REPORT.md)、[GEPA 论文](https://arxiv.org/abs/2507.19457)。

ICFA 研究两者之间的一个具体环节：**诊断文字在成为优化依据之前，应当通过什么检查。** 它保留已有优化器，并对输入优化器的诊断实施额外约束。

## 二、关键发现：结果、责任与控制权需要分别判断

### 1. 评价完整性影响分数的解释

研究在固定版本的评价组件中复现了一个边界：当任务存在待检查断言时，缺失或错配的部分评价结果仍可能获得通过分项。针对预定义异常建立的完整性检查，保留了 120 项有效控制结果，并将 440 项指定异常标记为无法判定。

这一结果确立了完整性检查的用途：避免把证据缺失直接解释为满足要求。上述数字属于受控输入测试，不代表真实运行中存在同等规模的评分错误。[受控结果](../../supporting-evidence/tau-feedback-evidence/results/OFFLINE_FINDINGS.md)

### 2. 显示为 Agent 消息，不等于由 Agent 策略产生

在真实交互诊断审计中，一条反馈批评 Agent 先问候、没有立即认证身份。源码和调用记录进一步表明，这段开场白由框架在首次模型调用前固定插入，真正的 Agent 回复已经提出认证要求。

研究随后以 12 个任务、3 种提示策略进行 36 次官方初始化控制，均得到相同开场白。这些检查没有调用模型，因而直接定位了该行为的生成环节：在所核验配置下，修改提示词不能改写此前由框架插入的开场。

**对话中的角色标记、实际执行来源和本次可修改范围，是三个不同属性。** 将它们混同，可能使优化建议指向错误的组件。[来源审计与初始化控制](../03-tau-feedback-evidence/E4_ACTION_ORIGIN_REVIEW.md)

### 3. 官方任务得分不能覆盖全部回答质量

在真实候选策略试验中，一个候选的两个验证任务均获得官方通过，但它额外作出了没有政策依据的退款时限承诺。两份分别记录的 AI 语义复核均认定这一承诺缺乏依据，按研究定义的合格标准，其中一个任务未通过。

这说明，任务评价器的覆盖范围与完整服务质量之间存在差异。研究据此将业务结果和答复依据分别验收。该候选最终未被采用；原优化器在得分持平时也保留了初始策略，因此不能把未采用的结果单独归功于新增验收机制。[候选与验证记录](../03-tau-feedback-evidence/G3_PILOT_RESULT.md)

## 三、方法设计：让反馈与具体修改对象相匹配

ICFA 将诊断视为需要核验的主张，按以下条件决定其使用资格：

| 核验层次 | 判断内容 | 方法作用 |
|---|---|---|
| 评价完整性 | 所需结果是否齐全，记录是否对应本次任务 | 防止缺失或错配证据被当作通过依据 |
| 行动时证据 | 当时的政策、消息和工具信息是否支持诊断 | 防止用隐藏答案或未来信息追责 |
| 来源与干预范围 | 被批评的行为由谁产生，本轮允许修改什么 | 避免把框架或其他组件的问题交给提示词优化 |
| 更新后的回归验收 | 新策略是否改善目标，是否引入额外错误 | 区分有资格尝试的建议与值得采用的修改 |

证据支持的诊断可以进入反思；有反证的诊断不予接纳；证据不足时保留不确定性。具有明确框架来源、且超出本轮提示词干预范围的行为，被标记为不适用于本轮提示优化，并注明应由相应组件审查。

这里的回归验收，是对修改后的策略重新执行任务，检查目标是否改善、原有能力是否退化。这一设计将改进过程分成两个决策：**先判断反馈能否指导本轮修改，再判断实际修改是否值得保留。** 来源匹配只赋予后续审查资格，不保证诊断正确，也不保证策略能够修复问题。[方法与实现](../03-tau-feedback-evidence/RESEARCH_REPORT.md)、[来源检查实现](../../supporting-evidence/tau-feedback-evidence/src/tau_feedback/action_origin.py)

## 四、理论解释：反馈使用资格具有干预相对性

### 1. 诊断成立，不足以推出当前干预有效

在初始化条件与外部输入固定的情况下，如果某个行为完全由框架生成、且不依赖待优化提示词，那么改变提示词无法直接改变这一行为。允许修改框架代码后，可用的修复方式才可能发生变化。

因此，反馈是否适合某轮优化，需要结合该轮允许实施的干预判断。这一分析借鉴了因果推断对观察、归责和干预的区分；这里建立的是组件控制范围约束，并不把执行来源等同于完整的因果效应识别。[Pearl，2009](https://ftp.cs.ucla.edu/pub/stat_ser/r350.pdf)

### 2. 筛选反馈存在质量与覆盖之间的权衡

更严格的准入可能减少错误建议，也可能排除值得尝试的建议。因此，需要同时评价接纳反馈的质量和有效反馈的保留程度。选择性预测研究中的“风险—覆盖率”框架，为这一问题提供了理论参照。[SelectiveNet，2019](https://proceedings.mlr.press/v97/geifman19a.html)

在有效、无效标签均可可靠确定的二分类模型中，设有效反馈原始占比为 p，有效反馈保留率为 t，无效反馈误收率为 f。若 0<p<1，且接纳概率大于零，由贝叶斯公式可得：

$$
P(\text{有效}\mid\text{接纳})=\frac{pt}{pt+(1-p)f}.
$$

因此，筛选后有效反馈占比提高，当且仅当 t>f。这一条件说明，拒收数量不能单独衡量筛选价值；机制需要对有效与无效反馈具有区分能力。该式是已有概率理论的直接推论；证据不足的反馈不能未经判定就并入无效类别，当前案例也不用于估计自然反馈中的这些概率。

## 五、受控验证：来源核对提供了什么增量

研究在调用前固定了 12 条合成反馈及参照标签，并分别核对语义准入和来源约束的结果。

| 参照类别 | 案例数 | 最终获得组合准入资格 |
|---|---:|---:|
| 依据充分 | 5 | 5 |
| 明确不支持 | 3 | 0 |
| 证据不足 | 4 | 1 |

单独的语义审查接纳了两条证据不足的建议。加入来源核对后，其中一条因涉及框架预置行为被排除，另一条仍获得资格。这个对照展示了来源检查的增量作用，也表明来源正确不能替代语义归责。

这些结果来自固定合成材料及 AI 参照标签，描述的是准入组件的行为；获得资格的建议没有在该项校准中送入 GEPA。策略试点生成的候选最终均未被采用，后续采用共同反馈的对照研究止于初始策略执行记录的核验阶段。因此，现有证据支持机制分析与局部校准，尚不构成任务成功率或优化成本改善的完整因果对照。[合成校准结果](../03-tau-feedback-evidence/C1_SYNTHETIC_RESULT.md)、[共享反馈研究记录](../03-tau-feedback-evidence/G4_STOP_RESULT.md)

## 六、研究贡献与适用边界

本研究的贡献可以归纳为三点：**识别反馈中的干预范围错配，建立可追溯的来源准入规则，并以受控案例区分语义判断与来源判断的作用。** 其方法价值在于为诊断、修改对象和验收结果建立明确的证据联系，使优化过程具有可检查的决策依据。

这种贡献建立在已有反思优化、归责和选择性预测研究之上。ICFA 的具体增量落在 τ2—GEPA 接入中的来源证据绑定、固定干预范围和不确定反馈处置，不能仅凭方法命名推导通用算法的新颖性。[相关工作比对](../../supporting-evidence/tau-feedback-evidence/research/FULLTEXT_NOVELTY_CHECK.md)

方法本身仍有四项重要边界。

**第一，执行来源依赖可观测的系统记录。** 当工具、框架和模型之间的记录不完整时，来源只能保持不确定。来源检查的可靠性取决于记录的完整性和可信程度。

**第二，来源清晰不能消除语义判断偏差。** 确认行为由模型生成，不等于确认它违反政策。审查模型之间也可能共享偏差，增加审查层数不自动产生独立证据。

**第三，保守筛选可能压缩探索空间。** 一条诊断即使归责不充分，其中仍可能包含有价值的子建议。整条拒收存在丢失有效探索方向的风险，需要区分责任判断与改进假设。

**第四，交互环境会参与塑造研究结果。** 用户的信息披露、目标变化和工具可见性都可能改变任务难度与责任判断。固定任务编号或模拟种子，并不自动形成相同的交互过程；从文本零售迁移到其他领域，也需要重新界定政策、证据和可修改范围。

## 结论

ICFA 围绕“什么反馈能够指导什么修改”建立了可审查的方法框架。研究表明，在智能体反思优化中，评价结果、行动证据与组件控制权需要分别处理；来源约束可以补充语义审查，明确反馈适用的修改对象。

这一工作为智能体优化提供了一个具体的研究方向：**把反馈到策略更新之间的推理过程显式化，并分别验证每一步是否成立。** 其价值体现为更清晰的归责边界、可追溯的准入决策，以及能够接受反例检验的优化方法。

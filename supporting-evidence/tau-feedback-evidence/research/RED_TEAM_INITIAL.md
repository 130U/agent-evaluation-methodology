| [VISTA](https://aclanthology.org/2026.acl-srw.8.pdf) | 分离语义假设与改写，逐假设验证，记录优化轨迹 | 显式假设与可解释更新记录不足以单独成立原创性 |

| [CAST](https://arxiv.org/html/2608.30147v1) | 行动时上下文验证、结构化 critique、零售训练和跨域实验 | 前缀可观察性原则直接重叠；必须增加这一类强基线 |

GEPA 官方 [adapter 接口](https://github.com/gepa-ai/gepa/blob/main/src/gepa/core/adapter.py) 允许传入自定义反馈和轨迹字段；因此“GEPA 没有某字段”不构成其无法支持证据核验的证明。此链接为访问日 main，正式执行应固定完整提交。

### CAST 对当前定位的具体影响

CAST 把部署时 verifier 定义为当前上下文和候选动作的函数，并排除未来观察；其标注器另外允许使用特权信息，训练后 critique 模型不接收这些信息。附录 E 明确提醒：用户计划里的订单等细节不代表用户已经在当前轮说出。它同时训练 critic 与 policy，支持在线 critique。以上是原文描述，未复现其数值。[CAST §3、附录 E](https://arxiv.org/html/2608.30147v1)

本项目可研究**既有诊断的离线选择性准入，以及这项筛选对固定优化器的净作用**；不应写“首次避免事后信息污染”。若与直接前缀 critique 的差异只能是改名，红队将判定创新性不成立。

## 4. 最小机制：先审核修改理由，再更新策略

### 4.1 真正需要新增的判断

对于原生 reviewer 给出的主张 `c`，定位到争议动作 `a_t`，构造：

`当时可见历史 H_<t + 待评动作 a_t + 冻结政策/工具定义 → 主张证据审核 → 支持 / 反驳 / 证据不足`。

审核应回答三个不同问题：

1. **义务成立吗？** 当时适用哪条政策、用户明确要求或必要信息收集规则？
2. **违反义务的证据是什么？** 证据必须指向具体消息、工具返回或动作，不能只引用 reviewer 自己的解释。
3. **修改建议可执行吗？** 一个只看到当时信息的 Agent 能否照做？建议应能改写为条件化策略，不能携带隐藏答案或实例 ID。

形式化地，可将准入规则写成 `admit(c)=supported_obligation ∧ supported_violation ∧ feasible_agent_correction`；三者任一不可判定则弃权，不能把弃权记为已证明无错。JSON 完整性只是这些判断可被读取的前提，不是机制本身。

### 4.2 三个容易写错的边界

- **必须给复核器待评动作。** 只有动作前历史而没有动作，无法判断具体行为是否违规。
- **行动后事实与行动前知识分栏保存。** 工具返回可以证明动作造成什么结果，但不能倒推 Agent 行动前已经知道该事实。
- **不知道答案仍可能有询问义务。** 若政策要求执行一次性换货前收齐目标，Agent 未询问就提交仍可成立策略错误。不能以“未披露”为由一律放行。

示意例子：用户当时仅说换一件商品，隐藏计划还有第二件。不能直接指责 Agent “没有替换第二件”；但若政策明确要求提交前确认全部换货目标，可以检查 Agent 是否履行了该义务。两个主张的举证条件不同。此例为设计说明，不是自然轨迹发现。

### 4.3 来源与准入必须分开

仅隐藏答案支持的诊断应记作 `insufficient_attribution`，不是自动判为用户错误。要认定用户、环境或标注错误，必须另有对应证据。完整上下文可用于独立资产审计，但这份特权证据不能未经转换变成在线 Agent 的具体行动指令。

输出保存原始主张、原始来源、审核结果、证据位置、策略可修改性、准入决定和拒收理由。接受的内容仍由同一 GEPA 改写；所有组使用共同验收规则。此阶段不另造一套优化器或只给 B2 加在线保护。

## 5. 最强基线与最小必要消融

### 5.1 基线

| 组 | 反馈处理 | 用途 |
|---|---|---|
| B0 | 原提示词冻结 | 展示起点，不能单独检验准入机制 |
| B1 | 原生 reviewer 的 Agent 类反馈 + 实际 GEPA | 必须尊重原生 user/agent 标签，保留原轨迹和政策访问 |
| B1-E | 与 B2 同格式、同审核证据包，但不强制准入 | 判断是否仅因为增加信息或格式而改善 |
| B1-P | CAST 思路的直接前缀动作 critique + 同 GEPA | 判断是否只需一次直接动作核验，根本无需“诊断再准入” |
| B2 | 原生诊断 + 上述选择性准入 + 同 GEPA | 待测方法 |

`B1-P` 是本研究实现的机制适配基线，**不是完整 CAST 微调复现**。应明示复用了什么、没有复现什么，不能拿论文表格直接与本实验比较。最强算法竞争者未实跑时，必须缩小“优于现有方法”的措辞。

另以等预算全文二次复核作为资源分配对照：相同的钱用于一般复核或多搜索候选，也可能获得同样收益。主比较按全部模型调用预算对齐；等候选次数只能作解释性附表。

### 5.2 最小消融

1. **随机等量准入**：匹配 B2 接受卡片数、尽量匹配长度，在同一候选池随机选取。随机种子固定，数量匹配成本与实际费用分开；这检验特定选择规则的价值。
2. **去时间边界**：保留结构审核和三态判断，允许全文/特权证据支持归责。检验行动时证据边界的作用。
3. **去可修改性/来源隔离**：保留证据审核，但把已有支持的所有来源都送入 Agent 策略更新。检验是否误把非 Agent 问题转成提示词规则。

B1-E 已提供“去硬门控”消融。共同回归验收不作为 B2 独占增量；无修改重跑属于干预解释对照。预算不足时分阶段完成，而不是省略后宣称每个组件都有效。

## 6. 真正能推翻正结论的观察

| 观察 | 应得结论 |
|---|---|
| 自然轨迹几乎没有此类误归责 | 目前只证明边界防护或挑战集鲁棒性，现实增益动机未建立 |
| B2 不优于 B1-E 或 B1-P | 未证明选择性准入的独立增量；可能只是丰富反馈或已有前缀核验的作用 |
| 随机等量筛选与 B2 相当 | 未证明准入规则比简单减少反馈更有价值 |
| 接受反馈更准确，但有效反馈拒收多、最终表现下降 | 准入存在负净效用，不能只报道精确率 |
| 只在开发任务恢复，冻结测试无收益 | 局部修复成立，泛化收益未支持 |
| 原提示词重跑同样恢复 | 不能把单次成功归因于策略修改 |
| 额外费用抵消表现改善 | 不能宣称同预算效率提升 |
| 改任务、换判分或只排除 B2 难例才有提升 | 比较不成立，应撤回性能归因 |
| 优势只体现在同源 LLM 评价，官方终态不改善 | 至少需要独立评价敏感性分析，不能自证 |
| 重复 rollout 很多但测试任务家族很少 | 只支持小规模观察，不能制造独立样本数 |

未显著不等于已证明无效；单个正点估计也不等于方向稳定。应同时报告配对差、区间、任务家族数、优化种子数与全部运行分母。

## 7. 执行前必须修补的设计风险

1. **量太小且验收过严。** 现协议试点只有 3 个验证任务，严格提升且零观测退化的组合容易造成所有候选被拒，或一次随机波动主导选择。可保留工程试点，但正式实验要以试点方差确定重复与验证量；不得看测试分数后修改阈值。
2. **组合机制无法归因。** 主实验先冻结最小准入机制；额外定向探测或在线 guard 各自成为消融。否则很难解释到底什么起作用。
3. **评分完整性与策略能力分开。** E0 原始输出检查所有组一致，官方原分与新增质量分并列保存。缺失转 unknown 的得分变化不能叫能力提升。
4. **AI 复核不是人工真值。** 可执行政策和精确证据优先；只有模型复核时如实标注。红队代理的同意不构成人工双盲校准。
5. **自然与构造样本分开。** 自然样本估计实际触发率，成对挑战样本验证边界；不把人为注入比例当线上误诊率。
6. **拒收后的 GEPA 行为必须定义。** 全部反馈被拒时跳过该次提议或按预注册规则处理，仍记录已花成本；不可偷偷把原始诊断重新传回优化器。

## 9. 无模型 API 时可做什么、不能证明什么

执行约束更新：主实现暂未发现可用模型 API 接入，正在核查用户已登录的本地工具。以下是继续推进完整目标的中间证据，不能据此宣布原定真实模型实验已经完成。

| 可执行工作 | 可以证明 | 不能证明 |
|---|---|---|
| 加载固定官方环境，调用真实工具，检查数据库状态与官方评价 | 工具/状态/评价接入正确，记录可重放 | Agent 会自主选择这些动作 |
| 向官方 NL 评价函数注入缺失、重复、类型异常等模型输出 | 明确输入下存在完整性缺口；修复遵守冻结的输出协议 | 真实 judge 的异常频率、自然任务影响 |
| 上下文投影的变形测试 | 未来或隐藏字段不能越过实现的信息边界 | 模型语义归责更准确、反馈更有价值 |
| 读取来源可核查的既有公开真实轨迹，做固定离线审计 | 对该历史模型与分布的事后证据 | 当前模型或优化后的真实交互表现 |

### 防止“合成缺陷—硬编码检测—完美结果”的循环论证

1. 先从上游接口、政策和数据模型写独立契约，再写实现；不要直接用实现分支列表生成全部测试。
2. 为同一表面异常准备正反例：无任何预期断言时空结果可以合法；有预期断言时空结果不完整。合法替代动作不能仅因不匹配示例就判错。
3. 确定性校验只能验证数量、身份、类型、时序和引用存在；“引用存在”不等于“引用支持语义主张”。后者没有模型或真实复核者时保持未验证。
4. 使用独立保留的挑战样例与变形组合，例如顺序打乱、嵌套重复、额外无关结果、动作/返回配对错位；记录样例由谁生成和规则是否看过它们。内部代理生成不等于独立人类标注。
5. 报告挑战类别、原始输入、判据和失败样例。检测率只对该挑战集合成立，不冠以 benchmark 准确率或真实反馈精确率。
6. 若关闭核心完整性/时间隔离逻辑仍全部通过，说明测试没有击中机制；修正测试，不增加漂亮但无关的样例数量。

### 信息边界的四项变形契约

- 固定 `H_<t` 与 `a_t`，任意替换动作之后的对话、任务终态和隐藏计划，**行动前证据包不变**。
- 删除或修改实际在动作前可见的事实，证据包相应变化；不能错误缓存原证据或制造缺失的信息。
- 改变争议动作本身，待审动作随之变化；不能因为前缀一致就沿用旧动作判定。
- 工具返回必须按调用 ID 和发生顺序归属：只把已收到的返回纳入行动前知识；未返回、失败或未知结果如实保留。

“证据包不变”应检验规范化字段及内容，不依赖文件名不同/相同这样的弱证据。相同输入不保证远程模型给出相同判断；这个实验只证明实现排除了特定信息通道。

最有价值的离线交付是**可执行的评价协议审计与信息边界测试套件**。它可以形成真实工程结果并服务后续实验，但单独通常不足以承担用户要求的完整反馈优化研究贡献。

| P1 | 错配工具返回被接受 | 返回 `id` 改为未请求值，投影照常成功 | 不能声称已验证调用/返回来源；应验证配对或明确上游已验证契约 |
| P1 | 用户侧私有工具信息进入 Agent 视图 | `requestor=user` 调用及返回被当作普通历史 | 官方 orchestrator 将这类返回路由给用户。本阶段仅支持零售，可明确拒绝用户工具；该测试不证明自然零售任务发生过泄漏 |
| P2 | 音频输入被当文本接受 | `is_audio=True` 且字符串 content | 当前范围是文本，应拒绝，不能静默删除音频标志后声称观察等价 |
| P2 | JSON 数值溢出绕过非有限值限制 | `1e400`、`-1e400` 被 Python 解析成无穷值 | `parse_constant` 只拦字面 NaN/Infinity；需校验解析后的数值或显式有限浮点解析 |

通过检查包括：无断言返回 not_applicable；有断言而空结果返回 unknown；完整失败返回 fail；排序不影响身份；重复预期文本按多重集合处理；重复返回不能代替不同断言；truthy 非布尔值不通过；嵌套重复键不通过；各绑定字段错配被识别；顶层 raw_data 与未来后缀被排除；前序事实和待评动作变化会改变证据包；防御性拷贝。

### 确认的能力限制，不应包装成修复后的强保证

- 伪造的语义解释只要字段合法仍能通过结构检查。独立测试特意保留这一结果，防止以后把结构 pass 写成事实正确。
- 请求绑定能发现随结果传来的可信元数据与预期不一致；若原始响应被替换、元数据保持不变，则当前设计不能识别。哈希不是签名，也没有认证生产者。
- 引用文字存在只能证明位置匹配。当前引用检查仅支持政策和历史 content，尚不能表达对待评动作、工具参数的结构引用；后续语义准入应补接口或明确不覆盖，不能把这一函数直接叫“证据支持验证”。
- 外部传入的 `policy`、`tool_schemas` 必须是冻结的 Agent 可见输入；当前投影不能认证调用者有没有把隐藏答案塞进这些可信参数。

### 对受控实验脚本的解释要求

40 条带断言任务上的同类故障变体不是 40 个独立自然异常；应报告“规则覆盖 × 任务配置”，不估计自然错误率。`cross_run_swap` 刻意改元数据，是绑定契约示范；上游评价器没有该契约，不能据此称其违反了原始评分职责。严格布尔类型等新增规则也是本研究选择的接口契约，需与上游允许类型转换的实际行为区分。单次本地计时可作为观测附表，不能宣称工业吞吐或稳定延迟优势。

## 13. E3 最终红队审查：预检异常不等于无法重放

本节更新第 12 节对 E3 的暂定用词。已读 `scripts/replay_archives.py`、`experiments/REPLAY_AMENDMENT.md`、`results/replay_experiment.json`，并核对官方 `EnvironmentEvaluator.calculate_reward` 与 `Environment.set_state` 的实际分支。

### 记录一致性

重新统计全部结果：1,824 个唯一 archive/run 组合，无缺失历史 DB 分项；1,536 个 `strict_replayed`，288 个 `invalid_reference_in_current_environment`。后者涉及 18 个 task ID，不等于 288 个独立任务。对 1,536 条逐行重算新旧 DB 分项差异计数为 0，与保存 summary 一致。没有非严格模式观测，因此该模式的差异率不可估计，不能与严格模式并列为另一项成功验证。

脚本按事前补充先执行参考动作，任何参考动作异常便暂停该记录的重评分。这是透明且保守的筛选规则，可以保留；**当前 `invalid_reference_in_current_environment` 只是内部状态标识，不能被解释为已证明该参考目标无效、历史轨迹不可重放或旧评分错误。**

### 两个异常样例与一个控制的独立执行

抽取第一份 Claude 零售归档中下列条目，使用固定当前环境复现参考动作，再额外直接调用官方严格评价器。额外调用仅用于说明预检异常的含义，不回写原实验主结果。

| task / run ID | 参考预检结果 | 异常当下 DB | 直接官方严格状态重放的 DB 分项 | 历史 DB |
|---|---|---|---:|---:|
| 2 / `ee6707bb-dbcb-4356-a43d-d91194bcf895` | `get_product_details`：Product not found；只读动作 | 未变化 | 1 | 1 |
| 13 / `d9dbc923-abfb-4ad2-940d-d891a9c3493f` | `return_delivered_order_items`：Payment method should be the original payment method；变更动作 | 未变化 | 1 | 1 |
| 6 / `4bec2b80-1781-4799-a103-037acd71715d` | 无异常 | 不适用 | 1 | 1 |

这两个反例直接表明：**参考动作预检失败不必然导致 DB 结果不同，也不必然阻止官方严格状态重放完成。** 只读动作失败尤其不能推导目标 DB 失效。即使失败动作具有变更能力，也必须另外检查最终目标状态和后续动作，不能仅看动作类别就宣布评分受影响。

### 必须保留的严格模式定义

当前上游 `set_state(strict=True)` 核对的是重放的**状态变更工具**返回内容；它跳过非变更工具，未知工具按既定 no-op 分支处理。因此，“严格”不是对每次历史工具查询、全文对话或全部模型输入逐项复现。官方 evaluator 也会捕获参考动作异常后继续形成目标状态；本研究另加的预检比这个路径更保守。

### 最终结论与用词修正

**E3 数据记录和所抽执行结果通过核对；严重风险在科学解释，不在已见计数。** 建议统一写为：

> 在 1,824 条公开归档运行中，1,536 条通过当前环境的参考动作预检，并在官方严格状态重放下得到与历史记录一致的 DB 分项；另外 288 条触发参考动作预检异常，按事前规则暂缓重评分，保留在总分母中。该结果检验的是当前版本下的状态重放兼容性，不证明历史评分有误，也不涉及新的 Agent 策略收益。

禁止将 288 条写成“历史误评分”“不可重放轨迹”“失败参考导致的错误评分”。若沿用内部 `invalid_reference` 字段，公开表注应明确它表示“预检异常后未纳入主比较”，并保留原始异常原因。

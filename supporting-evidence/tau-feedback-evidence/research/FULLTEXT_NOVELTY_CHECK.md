# AgentGrad / HarnessEvolve 全文核查：动作来源与干预范围

日期：2026-09-17。范围仅为两篇 arXiv v1 的方法、算法和实验段落，以及本地 `action_origin.py` / `g3_optimization.py`；没有调用 CLI 模型、复现两篇论文或读取 G3 在途轨迹。页码为 PDF 从 1 开始的页码。此次检索发生在 N1/E4 发现和 G3 设计之后，不能追记为实验前依据。

## 判断

**目前最稳妥的定位是：已知归责与受约束优化思想在 τ2—GEPA 上的具体适配，包含一个可独立检验的来源准入实现与失效案例；尚不足以主张新的通用优化算法。** 这也不是两篇方法的直接复现：本项目没有实现它们的整套优化过程。已有实现的区别可以准确描述，学术原创性和实际收益仍不能由“实现不同”推出。

## 1. 原文已经明确的内容

### AgentGrad：2026-09-08，2609.08572v1

- **算法**：对失败按 Agent 逆序逐个注入训练提示，重跑并以最终奖励判定修复目标；提示可来自答案或约束。修正输出用作中间监督，再聚类反馈、更新提示，经训练小批次和验证集双重改善才接纳。见 §4.1–4.4，pp.4–6，算法 1 p.5。[固定版本全文](https://arxiv.org/pdf/2609.08572v1#page=4)
- **实验**：§5.1–5.3、表 1–3，pp.6–8，比较包含 GEPA；五个任务集、两个模型，主表三种随机种子，并拆分目标识别、中间监督、语义抽象消融。这不是 τ2 来源审计。[实验原文](https://arxiv.org/pdf/2609.08572v1#page=6)
- **约束本项目的推断**：修复对象识别和反馈后验验收已被直接研究。其干预结果提供的“该修改能解决失败”证据，比本项目当前的“该动作在可变组件范围内”更强；二者不能等称因果归责。

### HarnessEvolve：2026-09-01，2609.00829v1

- **算法**：答案引导并核验参考轨迹，依据首次动作分歧诊断、聚类，再改提示/工具/代码；无参考时仍诊断。质量门检查候选泄露及膨胀，性能门检查当前与回放批次，最后验证集选快照。见 §3.2–3.5，pp.4–7；附录 B/C 算法 1/2，pp.13/15。[方法全文](https://arxiv.org/pdf/2609.00829v1#page=4)
- **实验**：§4，pp.7–9，五个数据集、跨框架转移；表 4 拆参考轨迹、聚类和质量门。实验的性能余量 δ=0、退化容忍 ε=0.025，因此不能概括为每步严格提升且零退化。[实验与消融](https://arxiv.org/pdf/2609.00829v1#page=7)
- **约束本项目的推断**：模块分工、门控及回归验收不是新增原则；其可改整个 harness，本项目仅改系统提示，两者对“可修”的边界不同。

两篇均为上述日期提交的预印本；这里只核验作者公开文本，未独立验证其性能主张。[AgentGrad 版本记录](https://arxiv.org/abs/2609.08572v1)、[HarnessEvolve 版本记录](https://arxiv.org/abs/2609.00829v1)。

## 2. 本项目具体增加了什么

以下是本地源码事实及本研究判断，不是上述论文声称的能力。

| 本项目机制 | 已有实现 | 不能推出的结论 |
|---|---|---|
| 来源证据绑定 | 用唯一 `cli_call_id`、调用角色、transport、原始输出和渲染消息/工具参数逐字匹配；支持固定 orchestrator 的 fresh/non-solo 初始化证据 | `role=assistant`、匹配一段文本或没有调用记录，都不能单独证明来源；宿主账本也不是恶意生产者的密码学认证 |
| 明示可变范围 | 仅支持 `agent_system_prompt_only`；模型动作可进入后续审查，框架/非 Agent 动作路由，未知来源弃权 | 模型所有的动作不一定能靠提示修好；框架动作也不意味着任何干预下都不可修 |
| 策略反馈准入 | G3 将原生诊断的语义接纳集合与来源资格集合取交集，沿共同隐私投影送入固定 GEPA | 当前顺序已经发生语义调用；不能宣称来源门节省了这些模型费用，也不能将 B2 组合效果拆给来源门 |
| 可复核的范围反例 | 已完成 E4 用实际初始化和调用绑定检查“框架种子消息被当作策略动作”这一具体边界 | 18 条框架消息不等于 18 次误诊；36 次零生成初始化不是策略优化收益 |

本地直接依据：`src/tau_feedback/action_origin.py:24,101`；`src/tau_feedback/g3_optimization.py:22,58`；`research/E4_ACTION_ORIGIN_REVIEW.md`。对两篇已读算法而言，我没有找到同样明确的“框架插入消息 / 实际模型调用 / 未知”三路证据绑定规则及其与固定可变字段的交集。**这是有限全文比对的观察，不是证明整个文献或两项目代码均不存在相同处理。** 本轮没有做外部代码审计，不将关键词未命中当作不存在的证据。

## 3. 独立增量能否成立

**已确认、可写入论文：** 在固定版本的 τ2 接入中复核了一个具体的归责范围盲点；给出了保守的来源资格规则、无法确认时的弃权和可重复的受控检查。将“语义诊断是否成立”“行为由谁产生”“本次干预允许改哪里”明确分开，是可审查的方法细节。

**仍需实证：** 这种范围错误在更广任务/框架中的频率、门控的精确率与覆盖率、是否影响候选吸收及最终收益。即使 G3 B2 优于 B1，也只有本次组合与优化路径的 pilot 证据；若需要声称来源模块的独立贡献，须另做同池、同语义决定、仅切换来源规则的消融。本轮不据此新增或改变冻结实验。

**最强反对意见：** 这可能只是固定初始化常量的一项适配修复；合理的优化器可能自行忽略该建议；排除诊断可能同时丢掉有用反馈；如果实际候选从未受该建议影响，来源门不会提高任务完成率。所有模型动作仍需语义与结果验证，不能用来源确定性掩盖诊断不确定性。

**建议表述：** “我们在固定 τ2—GEPA 流程中研究反馈的干预范围错配：以执行来源证据限定可用于系统提示优化的诊断，并通过受控初始化和后续预登记试验区分来源正确性与优化效果。”不使用“首次”“通用因果归责”“已证明提高泛化”等措辞。本轮未取得、也未读取 G3 结果，不能预写正向结论。

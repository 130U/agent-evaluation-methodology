# 无模型 API 路线：实测结果与研究结论

日期：2026-09-17。所有数值由结果JSON生成。

## 结论

研究问题成立：评价结果即使能被解析，也不一定覆盖了任务要求；历史反馈即使带有正确的任务ID，也不一定与当前任务、工具和评分版本兼容。本项目已复现具体失效条件，并实现可检验的准入约束。

本轮证据支持评价与反馈基础设施的可靠性改进。它尚不能说明某个模型在经过GEPA优化后完成任务更多、回归更少或成本更低。结构保护、语义归责和策略收益是三个需要分别验证的问题。

## 为什么可以在没有 API 的条件下做

1. 官方公开了包含模型交互、工具调用和评价记录的历史轨迹，可直接进行只读审计。
2. 官方零售数据库、工具和状态评价器可以本地执行，历史动作可被真实重放。
3. 在真实评价类的模型返回边界注入指定输出，可观察解析和聚合行为，无需生成新的交互。

没有把脚本生成的输出叫作模型响应，没有借用官方模型分数作为本项目优化收益。

## E0：公开历史轨迹

覆盖4种模型、114个任务、每模型每任务4次，共 **1824次历史运行**。文件字节、Git blob和SHA256均核验。完整得分及pass^k见[归档审计](ARCHIVE_AUDIT.md)。

在有期望的128次NL检查与608次COMMUNICATE检查中，未发现记录数量、身份、重数或字段类型异常。这是对所保存记录的结构检查，不是语义正确率，也不是当前评价器自然异常率。

历史任务采用DB＋COMMUNICATE；当前114个任务的评分依据均已有变化。NL断言从8个任务、12条扩展到40个任务、61条，7个任务的参考动作内容改变。按同一task ID直接混合两种评价口径不成立。

## E1：真实评价类的受控故障实验

完整准入组件保留 **120项有效控制**（80项pass、40项fail），将 **440项预定义异常**标为unknown；74个无断言控制为not_applicable。JSON损坏及顶层类型错误在上游共引发80次异常，不能写成这80次被上游错误判通过。

最直接的缺陷证据是：要求非空断言时，缺少结果、空结果、漏项或断言错配仍可能使上游NL分项为1。分项通过不等于整项任务通过。

布尔强类型与跨运行绑定是本项目增加的契约要求；前者不能一律写成上游错误判定，后者也不属于原有单次评分函数的职责。固定故障按规则被拦截是工程符合性结果，不能单凭其检出率主张新的学习算法或实际收益。

## E2：行动时信息范围

在1824条归档中按事先写入脚本的规则各选一个Agent动作：优先首个状态变更工具动作，其次首个工具动作，再其次首个Agent消息。未来消息与隐藏元数据改变后，全部视图保持不变；当前动作与政策改变后，全部视图相应改变。

1,822条记录有先前用户消息，对该消息的修改全部影响视图；其余2条不适用，没有伪计为通过。工具调用/返回ID被保留并校验，用户侧私有工具与音频输入被明确拒绝。

四份归档均未保存tool_defs，因此该实验验证消息和政策投影，不能声称重建了历史模型的完整输入。字符串引用存在仅证明位置可追溯，不能证明该引用支持错误归因。

独立红队先发现5个实现问题，其中包括原生工具返回ID丢失和用户工具泄漏；修复后原24项测试全部通过，未修改测试预期。另有48项归档公式、异常分母和原始数据交叉核对测试通过，总计72项。

## E3：历史动作在当前环境中的重放

全量1824条记录均保留。**1536条**通过参考动作预检后完成官方严格状态重放，数据库分项与历史记录的差异为 **0条**。本次没有进入非严格重放。上游的严格模式主要核对变更工具返回，不重执行所有只读调用，因而不称为完整历史交互复现。

另 **288条**涉及18个任务，参考动作预检至少一步出现异常，按事前规则暂缓重评分。任务ID为：`2, 3, 4, 12, 13, 21, 35, 37, 38, 39, 46, 47, 54, 55, 64, 67, 68, 105`。

这是一条兼容性告警，不是历史总分错误或轨迹不可重放的证据。红队抽查任务2和13：绕过本研究预检门后，官方严格状态重放仍得到与历史一致的DB分项1。因此，预检异常本身不能证明终态不同。历史运行提交本次无法取回，不能区分原参考动作问题、工具变化与数据库变化的全部原因。

## 方法定位与论文可支持的表述

反馈优化的前提是输入证据可解释。我们把断言覆盖、记录上下文和行动时信息范围分开检查，使证据缺失或上下文不兼容的评价进入弃权状态，避免直接作为策略修改依据。实验表明，这些规则能拦截指定的结构故障，同时保留本次有效控制；真实归档复核揭示了跨版本复用的兼容性限制。

行动时可见信息约束已有[CAST](https://arxiv.org/abs/2608.30147)等先例；[GEPA](https://arxiv.org/abs/2507.19457)已有反思式优化。本项目的后续增量应当在固定GEPA下检验既有反馈的选择性准入，报告错误流入、有效建议拒收、额外验证成本和最终任务收益，不能以重命名已有方法代替创新。

## 尚未取得的证据

- 没有自然反馈语义真值，不能报告自然误归因率。
- 没有新的Agent或GEPA实验，不能报告成功率提升、未见任务泛化或优化成本收益。
- 已有实验是公开数据的全量描述和预定义故障的确定性检验，不适合把重复样例包装成独立统计显著性。
- 工程模块已复核；完整语义准入器、模型适配、优化与候选验收仍需实现和执行。
